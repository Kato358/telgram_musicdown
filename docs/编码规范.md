# Telegram 音乐下载器 — 编码规范

| 项 | 内容 |
| --- | --- |
| 文档版本 | v1.0 |
| 上游文档 | SRS v0.3、SDD v1.0 |
| 日期 | 2026-09-20 |
| 适用范围 | `app/` 后端 Python、`web/`（如单独建仓则为前端目录）Vue 3/TS |

规范按「工具强制 → 约定 → 反例」组织。凡工具能强制的项（格式化、lint）不靠人肉遵守，CI 卡死。

## 1. 工具链与强制规则

### 1.1 Python（后端）

| 工具 | 配置 | 作用 |
| --- | --- | --- |
| Python 版本 | 3.11+（SRS §4.2 锁定） | — |
| 格式化 | `ruff format` | 唯一格式化器，禁止手调格式 |
| Lint | `ruff check` | 规则集见 1.2 |
| 类型 | `mypy`（`strict = true` 于 `app/services`、`app/db`、`app/utils`；`web/routes` 允许 `disallow_untyped_defs = false` 过渡） | FastAPI 依赖类型标注生成 OpenAPI |
| 测试 | pytest + pytest-asyncio | `asyncio_mode = "auto"` |
| 依赖 | `uv`（或 pip-tools 锁定 `requirements.lock`） | 禁止无版本上界的手写 `requirements.txt` |

### 1.2 ruff 规则集（`pyproject.toml`）

```toml
[tool.ruff]
line-length = 100
target-version = "py311"

[tool.ruff.lint]
select = [
  "E", "W",       # pycodestyle
  "F",            # pyflakes
  "I",            # isort（import 排序）
  "B",            # bugbear（常见 bug）
  "UP",           # pyupgrade（3.11 语法）
  "ASYNC",        # async 陷阱（阻塞调用、未 await）
  "S",            # bandit（安全；按 4.1 豁免表放行）
  "SIM",          # 简化
  "PTH",          # 用 pathlib 替代 os.path
  "RET",          # return 简化
  "T20",          # 禁止 print（用 logging）
  "PL",           # pylint 子集
]
ignore = ["PLR0913"]  # 函数参数数不设限（FastAPI 依赖注入常见多参）

[tool.ruff.lint.per-file-ignores]
"tests/**" = ["S101", "PLR2004"]  # 测试允许 assert 与魔法数
```

### 1.3 前端（Vue 3 + TypeScript）

| 工具 | 配置 |
| --- | --- |
| 语言 | TypeScript `strict: true`，禁止 `any`（确需时 `unknown` + 收窄） |
| 格式化/Lint | ESLint（flat config，含 `eslint-plugin-vue` flat/recommended）+ Prettier；`npm run lint` 一键 |

## 2. Python 编码约定

### 2.1 命名

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 模块/包 | `snake_case`，单数名词 | `services/download.py` |
| 类 | `PascalCase` | `DownloadService`、`PathBuilder` |
| 函数/变量 | `snake_case`；布尔前缀 `is_/has_/should_` | `is_audio_message()` |
| 常量 | `UPPER_SNAKE`，模块级 | `MAX_PATH_BYTES = 230` |
| 私有 | 前缀 `_`；禁 name mangling 双下划线（测试难 mock） | `_render_segment()` |
| 异常类 | 后缀 `Error` | `LinkParseError` |
| Pyrogram 实体 | 保持官方名 `msg.audio`，不重命名收窄 | — |

### 2.2 类型标注

- 所有公开函数/方法完整标注参数与返回值；`Optional[T]` 用 `T | None`。
- `dict`/`list` 用内建泛型：`dict[str, Any]`、`list[Task]`（禁 `typing.Dict`）。
- Pydantic 模型（API 请求/响应）放 `web/routes/schemas.py`；**禁止**裸 `dict` 进出路由。
- DB 行：`db/models.py` 用 dataclass 或 `sqlite3.Row` → dataclass 转换函数，字段名与 SDD §3.2 一致。

```python
# 好
def render_path(track: TrackMeta, cfg: TemplateConfig) -> PurePath: ...

# 坏：裸 dict 穿透三层
def render_path(track: dict, cfg: dict) -> str: ...
```

### 2.3 异步

- `async def` 内**禁止**任何阻塞调用（文件 IO 用 `anyio.to_thread.run_sync` 或 `asyncio.to_thread`；mutagen 是同步库，标签读写必须 `to_thread`）。
- 信号量/锁/队列一律 `asyncio.*`；禁止 `threading`（SDD §1.3 并发模型单 loop）。
- Pyrogram 调用必须经 `telegram/flood.py` 的 `with_flood_retry()` 包装，禁止裸调 `download_media`/`search_messages` 后自行 try FloodWait。
- 任务取消友好：长循环每批检查 `asyncio.current_task().cancelling()` 或取消标志，禁止 `shield` 包裹下载（暂停功能依赖取消）。

```python
# 好：写标签进线程池（NFR-10 + 不阻塞 loop）
await asyncio.to_thread(write_tags, path, meta)

# 坏：同步 mutagen 直接卡死 SSE 与 TG 心跳
write_tags(path, meta)
```

### 2.4 错误处理

- 自定义异常层次：`app/errors.py` 定义基类 `AppError(code: str, message: str)`，子类按域（`LinkParseError`、`SourceUnreachableError`、`TagWriteError`…）。FastAPI 全局 handler 统一转 SDD §4.1 错误包络。
- **禁止**裸 `except:`；`except Exception` 必须记日志并带 `logger.exception`，不得静默吞掉（NFR-08：每个失败任务有人类可读原因）。
- 底层客户端异常（FloodWait、ChatAdminRequired 等）在 `telegram/` 层捕获并翻译为领域异常，**services 层不得 import pyrogram**。
- 任务失败必须把 `error` 写入 `tasks`/`history` 表再抛/返回，Web 可见（SRS FR-DL-04）。

```python
# 好：telegram 层翻译
try:
    msg = await client.get_messages(chat_id, ids=[mid])
except RPCError as e:
    raise SourceUnreachableError(reason="not_joined") from e

# 坏：services 层直接吃 pyrogram 异常类型
```

### 2.5 日志

- 统一 `logging`，模块级 `logger = logging.getLogger(__name__)`；禁 `print`（T20 强制）。
- 级别约定：`DEBUG` 调试细节 / `INFO` 任务状态转移 / `WARNING` 可恢复异常（FloodWait 等待、去重跳过）/ `ERROR` 任务失败。
- **禁止**记录：手机号、验证码、`api_hash`、`bot_token`、session 内容（SRS FR-OPS-03）。日志工具函数 `redact()` 对 URL 查询串与已知敏感键脱敏。
- 结构化字段用 `logger.info("download finished", extra={"task_id": t.id, "path": t.save_path})`；`logs/` 滚动（RotatingFileHandler，10MB × 5）。

### 2.6 SQL 与数据访问

- 所有 SQL 收口 `db/store.py`；参数化查询（`?` 占位），**禁止** f-string/`%` 拼 SQL。
- 事务边界在 store 方法内：`with db.transaction():`；写 `history` 与 `tasks` 关联更新必须同事务。
- 迁移：`db/migrations/NNN_*.sql` 顺序编号，启动时按序执行并记 `schema_version`；禁止改历史迁移文件。
- 时间戳统一存 UTC ISO-8601 文本（`created_at` 等），展示层转本地。

### 2.7 路径与文件名（Windows 优先环境）

- 路径一律 `pathlib.Path`（PTH 强制）；落盘前必经 `utils/sanitize.py`：非法字符替换、保留名检查、≤230 字节截断（SRS FR-DL-03）。**禁止**绕过 sanitize 直接 `open()` 用户可控路径。
- 磁盘写入模式固定：先写 `temp/`，校验后 `os.replace()`（原子）；禁止直接写 `save_path`。
- 所有用户可见路径由服务端从 DB id 拼装；路由层禁止接受 `?path=`（NFR-02）。

## 3. Git 约定

### 3.1 分支与提交

- 分支：`main`（可发布）+ `feat/<id>-<slug>` / `fix/<id>-<slug>`；禁止直接 push `main`（CI 门禁）。
- 提交信息：Conventional Commits，英文 type + 中文描述皆可，但 type 必须规范：

```
feat(search): 支持跨页批量选择
fix(download): FloodWait 后重试计数未写入 tasks 表
refactor(path-builder): 提取渲染段函数
```

- 一次提交一个意图；混格式化与逻辑改动 → 先单独 `style:` 提交格式化。

### 3.2 敏感与产物（NFR-02）

`.gitignore` 必含（SDD §6）：

```
config.yaml
.env
sessions/
data/
temp/
downloads/      # save_directory 默认相对目录
logs/
library/        # 旧默认目录（兼容保留）
```

提交前自查：`git diff --staged` 中出现任何密钥值即中止。历史已泄密钥作废重发，不做"从历史抹除"。

## 4. 测试规范（NFR-07）

### 4.1 结构与命名

```
tests/
├── unit/            # 纯函数：path_builder、linkparse、sanitize、去重、退避
├── service/         # FakeUserClient 注入：状态机、暂停、媒体组、LRU
└── api/             # httpx AsyncClient + 临时 SQLite（tmp_path fixture）
```

- 文件 `test_<模块>.py`，用例 `test_<行为>_<条件>_<期望>`：

```python
def test_render_path_album_missing_omits_album_segment() -> ...   # 好
def test_render_2() -> ...                                        # 坏
```

### 4.2 编写规则

- 每用例独立：不共享可变 fixture 状态；DB 用 `tmp_path` + 每用例新建。
- 断言**可观察行为**（返回值、DB 行、文件存在与大小、HTTP 状态码与包络），禁止断言实现细节（内部调用次数、私有字段、日志措辞）。
- AAA 结构（Arrange-Act-Assert）；单用例单断言主题，多 assert 允许但同主题。
- 假 Telegram 客户端 `FakeUserClient`（`tests/fakes/`）实现真实协议面：`search_messages / get_chat / get_messages / iter_messages / download_media`，可脚本化注入：正常返回、FloodWait、大小不符、非音频。**单测禁止真实网络**。
- 参数化用 `@pytest.mark.parametrize` 覆盖边界：模板回退链每级、空段省略、冲突序号、4 类链接 URL、Windows 保留名。

### 4.3 必测清单（映射 SRS 验收）

| 必须有用例的行为 | 出处 |
| --- | --- |
| 损坏文件（大小不符）不落 `save_path` | NFR-01 |
| FloodWait 注入 → worker 挂起后重试、不无视等待 | NFR-09 |
| `voice`/视频消息不入队 | 验收 #11 |
| `{album}` 缺失省略目录段；`{artist}` 回退 Unknown Artist | FR-NAME-03 |
| 0.0.0.0 无密码启动报错退出 | FR-WEB-02 |
| 无会话请求 `/stream` 401 | 验收 #16 |
| 标签写失败回滚、音轨字节不变 | NFR-10, 验收 #18 |

## 5. 前端编码约定（补充细则）

- API 调用统一 `src/api/client.ts`（封装 fetch：cookie、错误包络解包、401 跳登录）；组件内禁裸 `fetch`。
- SSE 订阅只在 `stores/events.ts` 一处；组件通过 store 消费，禁止组件各自 `new EventSource`。
- 样式：TailwindCSS utility class 优先；自定义样式用 CSS 变量（主题切换依赖）；禁行内样式（动态值除外）。
- 音频播放：全局唯一 `<audio>` 实例挂 `PlayerBar`；切歌先 `pause()` 再换 `src`（SDD §5.4）。
- i18n：所有用户可见文案走 `vue-i18n`，组件内禁止硬编码中英文案。
- 时间/大小展示统一 util：`formatDuration(sec)`、`formatSize(bytes)`、`formatDate(iso)`。

## 6. 反模式清单（CR 必拒）

| 反模式 | 后果 | 替代 |
| --- | --- | --- |
| services 层 import pyrogram | 无法用 FakeUserClient 单测（NFR-07） | telegram 层翻译为领域异常 |
| 裸 `dict` 穿路由 | 类型丢失、OpenAPI 无契约 | Pydantic schema |
| 直接写 `save_path` | 损坏文件入库（NFR-01） | temp/ → 校验 → `os.replace` |
| 自行 try FloodWait 各处重复 | 退避策略漂移 | `with_flood_retry()` 单点 |
| `# type: ignore` 无注释 | 类型检查形同虚设 | `# type: ignore[具体码]  // 原因` |
| try/except pass | 违反 NFR-08 | 记日志 + 状态落库 |
| 组件内 `new EventSource` | 多连接打爆 SSE | `stores/events.ts` 单例 |
| 测试 mock 被测对象本身 | 测试恒真 | FakeClient 注入依赖 |
| 硬编码文案/颜色 | i18n、暗色主题失效 | vue-i18n / CSS 变量 |
| `git add -A` 提交 | 泄 session/密钥（NFR-02） | 显式 add 文件列表 |

## 7. 注释与文档

- 注释解释**为什么**，不复述代码；过时注释是 bug，改代码必须同步注释。
- 公开服务方法（`services/*` 顶层类方法）写一行 docstring：职责 + 对应 FR 编号（如 `FR-DL-03`），便于追溯。
- TODO 格式：`# TODO(<owner>): <事项> <追踪方式>`；禁止无主的 `TODO`/`FIXME` 合入 main。
- 禁止提交注释掉的死代码；需要历史找 git。
