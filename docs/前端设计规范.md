## 1. 设计定位

**产品**：本地常驻的私人音乐库控制台——一个人、一台服务器、一个自己的曲库。**主要任务**：把 Telegram 频道里的音频按自己的命名规则稳落到本机磁盘，之后还能找到它、播它、确认它在不在。

设计身份由三件事构成，其余全部克制：

1. **亮绿是唯一的「在做」信号**——主按钮、激活导航、播放主键、进度填充。全站只有一个**强调色**，不引入第二套；v3.4 的分类色板（蓝/紫/琥珀）不是强调色，它只给统计卡的图标分类（§3.5），不碰按钮、进度与激活态。
2. **卡片化的事实分区**——页面底薄荷、卡片纯白并浮起（`--card-shadow`）、淡绿出现在「页面级入口」（横幅与侧栏曲库卡的命名渐变）与「已被选中」的导航项上。颜色永远表达状态或层级，不表达装饰。
3. **波形进度**是这一屏的签名元件——底部播放条用纵向声波柱代替线条，它是全站唯一「可以被记住」的形状。

不做：营销 hero、逐卡入场动画、第二强调色、设计稿之外的颜色、渐变面用在命名两处之外（§3.5）、统计卡与快照之外的第三类数字来源。

v3.4 起允许的三件「装饰」，全部收在命名位置与命名令牌里，越界即视为违规：

| 允许 | 位置 | 约束 |
| --- | --- | --- |
| 渐变面 | 横幅（仪表盘一次 + 下载页一次）、快速操作卡头 | 只能取 `--gradient-banner` / `--gradient-brand`，不得在页面里写字面量 |
| 分类色 | 统计卡图标底 + 图标 | 四档固定（primary/blue/violet/amber），不新增第五档，不做按钮与文字色 |
| 装饰图形 | 横幅右侧 | `aria-hidden`，不参与布局、不承载信息、不响应点击 |

横幅是**同一个件**（`HeroBanner`，§5.5）在两页各出现一次：仪表盘的是「欢迎 + 内联搜索」，下载页的是「开场 + 说明」（无输入框，入队入口在队列卡的「添加链接」里）。两处都不写营销话术——标题与说明回答「这一页能做什么」。

### 2.2 间距令牌

| 档位 | 值 | Tailwind | 用途 |
| --- | --- | --- | --- |
| 页面外边距 | 24px | `p-6`（<768px `p-4`=16px） | 内容区外边距 |
| 卡片内边距 | 24px | `p-6`（紧凑卡片 `p-5`=20px） | 卡片内边距 |

间距直接使用 Tailwind 4 的 4px 基准刻度，**不在 `app.css` 里另立 `--space-*` 令牌**；上表只是把数值钉死，避免各处自选。表格行**不用** `gap`，用 1px 分割线 + 固定行高（§5.3）。

### 2.3 圆角令牌

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--radius-card` | 16px | 大卡片、容器、浮层菜单、横幅的音符方块 |
| `--radius-nav` | 12px | 导航项选中块、表格卡片内的次级块 |
| `--radius-control` | 10px | 输入框、按钮、路径框、下拉 |
| `--radius-chip` | 8px | 标签 chip、徽章、封面缩略图、小图标按钮 |
| `--radius-pill` | 999px | 播放主键、头像、搜索框、状态点、进度条 |

`app.css` 的 `@theme inline` 把五个令牌注册为 `rounded-card / rounded-nav / rounded-control / rounded-chip`（`--radius-pill` 直接用 `rounded-full`）。shadcn 的 `--radius` 保留并设为 `10px`（= `--radius-control`），使 `ui/` 生成物的 `rounded-md/lg` 自动落在本尺度上。

`ui/` 生成物的落点钉死如下（生成物可改样式、勿改 API）：**浮层与容器**（`dialog-content`、`dropdown-menu-content`/`sub-content`、`select-content`）一律 `rounded-card`，不得沿用 shadcn 默认的 `rounded-xl/lg`——它们在本尺度里是 12px/10px，会把浮层做成比卡片还方的块；**控件**（`input`、`textarea`、`button`、`select-trigger`）保持 `rounded-lg`（= 10px）；**复选框**用最小的 `rounded-sm`（6px，`app.css` 已留存该令牌供 shadcn 的 `rounded-sm` 落点），**开关/开关把手/药丸件**用 `rounded-full`。除此之外不得出现 `rounded-[4px]` 这类令牌外字面量。

### 2.4 卡片浮起

卡片 = `--card` 底 + 1px `--border` + `--card-shadow`（极浅双层投影）。三项都在 `app.css` 的 `.card` 工具类里落地，页面不得自行加阴影或改圆角：

| 令牌 | 浅色 | 深色 |
| --- | --- | --- |
| `--card-shadow` | `0 1px 2px rgb(16 24 40 / 0.05), 0 14px 30px -22px rgb(16 24 40 / 0.28)` | `0 1px 2px rgb(0 0 0 / 0.45), 0 14px 30px -22px rgb(0 0 0 / 0.7)` |

浮层（`dialog` / `dropdown-menu` / `select`）沿用 shadcn 的 `shadow-md` / `shadow-lg`，不并入本令牌；`--background` 换薄荷底后，凡「浮在卡片上」的件不得再用 `bg-background` 取底色（outline 按钮取 `--card`、开关把手取 `--card`）。

### 2.5 仪表盘栅格（v3.4）

| 断点 | 主栏 | 右栏 |

| ≥1024px（`lg`） | `minmax(0,1fr)` | `minmax(260px,0.45fr)`——按比例，不写死像素：主栏:右栏 ≈ **2.2 : 1**（右栏占内容区 ~31%） |

- 外层：`grid items-start gap-4 lg:grid-cols-[minmax(0,1fr)_minmax(260px,0.45fr)] lg:gap-6`；两栏内部各自 `flex min-w-0 flex-col gap-4`。
- 间距照参考图实测钉：**列间距 24px**（参考图量到 26px）、两栏内部纵向 16px、统计卡之间 20px（`gap-4 sm:gap-5`，参考图量到 20–22px）。
- **比例来自参考图实测**：参考图 1152px 宽下，内容区 ~932px、右栏 ~282px、右栏占 30%；同一比例用 `0.45fr`（1:0.45 = 2.22:1）复现。写死 `280px` 只在 1152px 那一档凑巧对，窗口一宽（1920px 时右栏只占 26%）比例就跑掉了。
- **断点取 `lg` 而不是 `xl`**：参考图的三栏在 1152px 就成立，把右栏压到 1280px 才出现的做法会让笔记本宽度下（1152–1279）掉回单栏，看起来完全是另一个页面。
- 统计卡栅格：`grid grid-cols-2 gap-4 sm:grid-cols-4`——≥640px 一律四列（主栏最窄处约 130px/张，正好是参考图的密度），<640px 两列。
- 右栏块顺序固定：快速操作 → 当前播放 → 系统状态（参考图的三块，一块不多）。「系统状态」是环境读数，永远排最后；它不能再被挤出首屏，所以**最近入库放在主栏**，排在下载任务表之后。
- 统计卡数值在 `<1280px` 用 `text-h2`：四列时列宽只有 ~130px，`text-h1` 的 24px 会让「117 MB」顶出卡片内边距。
- 其余视图仍走 §2.1 的单栏 `max-w-[1100px]`；下载页统计卡 4 列（`grid-cols-2 xl:grid-cols-4`）、音乐源页 3 列（`grid-cols-2 lg:grid-cols-3`），不引入第五种栅格。
- 右栏不进 `overflow` 裁剪：面板里的下拉/浮层仍由 shadcn portal 承载，不受栅格影响。

### 2.6 下载页栅格（v3.8）

**单栏通列，无右栏**：横幅（含统计卡）→ 下载队列 → 记录表卡，自上而下一条线。

- 外层：`flex min-w-0 flex-col gap-4`——一条主栏吃满内容区宽度，不再按断点分栏。
- **v3.8 起移除右栏**（v3.6/v3.7 是 `minmax(260px,0.5fr)` 的 2.00:1 双栏）：右栏三张卡全是主栏的镜像（队列窄镜像 / 已入库页签前三行 / 横幅统计卡复读），不产生新信息；移除后 `lg` 档主栏从 ~590px 回到全宽（1152px 窗口下 ~932px），v3.7 为塞右栏做的两条表格妥协随之撤销——**专辑列回到 `lg` 出现、行/表头列间距回到 12px**（§5.3）。
- 横幅与统计卡是**一块**：`HeroBanner` 的 `children` 插槽接住统计卡栅格 `grid grid-cols-2 gap-3 sm:grid-cols-4`，卡片坐在横幅的淡绿上（§5.5）。单栏后这一块吃满全宽，四张统计卡在 `lg` 档每张 ~220px，比双栏时宽松。
- 全部内容块都是主栏卡：队列卡、记录表卡（页签 + 搜索 + 批量 + 表格 + 页脚）。进行中的项只在队列卡出现（有控制与实时读数），记录表不再重复状态与进度两列。
- 窄屏（<1024px）与 v3.7 相同：块序即阅读顺序，只是不再有「右栏三卡落到表格之下」的第二段——没有右栏，也就没有落点。

### 3.2 深色态是派生态，不是第二套设计

浅色为默认主题（`index.html` 首帧内联脚本：`tgm-theme` 为 `dark` 或系统深色时才给 `<html>` 加 `.dark`）。深色态**只覆盖 §3.1 与 §3.5 的同一批令牌**，色相与语义角色不得改变，不得新增令牌。上表深色列是 §3.1 浅色值的机械派生：底色由薄荷转深绿灰（`#101613`），主色提亮到 `#4FB08A` 并配深色前景 `#06120C`（v3.0 的 `#3E9C76` 于 `--primary-soft` 底只有 **4.38:1**，低于 4.5 底线，v3.1 一并修掉）；`--destructive` 族取自 v2.0 已有的 `#FF6B6B`/`#DC7159` 家族，避免新增色相。

### 3.3 对比度底线（不是建议）

- 正文与关键副文本 ≥ 4.5:1；非文本控件（图标、状态点）≥ 3:1。
- 实测（v3.1 配色，浅色 / 深色）：`--primary` 于卡片底 **5.34 / 6.21:1**、于 `--primary-soft` 底 **4.69 / 5.57:1**；主色底上的文字 **5.34:1**（白）/ **7.19:1**（深色 `#06120C`），hover 底 **6.53 / 7.26:1**；`--muted-foreground` 于卡片 **5.98 / 6.52:1**、于薄荷底 **5.43 / 7.25:1**、于 `--primary-surface` 底 **5.32 / 6.40:1**；`--destructive-text` 于白底 **4.98:1**；`--destructive`（非文本）于白底 **3.71:1**；状态灯 `--lamp-done` **5.33 / 7.32:1**、`--lamp-idle` **3.64 / 4.37:1**（非文本，达标）。
- **`--faint-foreground`（`#7C8797`）于白底 3.64:1，不达 AA**——故它只用于**冗余**字段（时长、大小、单位：同一信息在别处仍可得），路径与歌手这类关键信息一律用 `--muted-foreground`。
- **`--border` / `--input`（`#E5E6EB`）于白底仅 1.25:1，低于 WCAG 1.4.11 对控件边界的 3:1**——这是与参考图一致的**有意取舍**：卡片的可辨识性由「薄荷底 ↔ 白卡」的明度差加 `--card-shadow`（§2.4）承担，描边只做收边。若要严格达标，把 `--border` 提到 `#8A93A2`（3:1）会把整屏线条明显加重，本版不采用。
- 浅绿（`--primary-soft` / `--primary-surface`）**只做底**，不得作为文字色或图标色。

### 3.4 落盘路径的排法

路径是产品承诺的物证，是列表行里的**一级文本**（第二行），不是脚注：

- 用 `splitPath()` 拆成「目录」+「文件名」两段：目录段 `truncate` 可省，**文件名段 `shrink-0`、永不被省略号吃掉**（扩展名是曲库的判断依据）。
- 整条路径挂 `title` 属性，悬停可见全量；「复制路径」给的是原文，不是省略后的显示值。
- 样式：`text-code`（12px `--font-mono`）+ `--muted-foreground`，单行。
- 文件不在磁盘时，这一行**整体替换**为 `--destructive-text` 的原因文案（§5.3）。

### 3.5 分类色板与命名渐变（v3.4 新增）

统计卡需要一眼分出「这是哪一类数字」，单靠同一个绿色做不到。于是引入**分类色板**：它只回答「哪一类」，不回答「好不好」——状态与错误仍然只有 `--lamp-*`、`--destructive*` 两队令牌，两者不得互相借用：下载页「失败」统计卡的图标是琥珀，它数的是**终态这一类数字**（§5.5）；而**行与状态灯上的失败**永远是 `--lamp-fail` 灯 + `--destructive-text` 文案，分类色不进状态灯。

| 令牌 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--accent-blue` / `--accent-blue-soft` | `#1D4ED8` / `#EAF1FF` | `#60A5FA` / `#16202E` | 蓝色分类：入库、曲目 |
| `--accent-violet` / `--accent-violet-soft` | `#6D28D9` / `#F3EEFF` | `#A78BFA` / `#241C38` | 紫色分类：占用、下载记录 |
| `--accent-amber` / `--accent-amber-soft` | `#B45309` / `#FDF3E3` | `#FBBF24` / `#2B2113` | 琥珀分类：源、终态 |
| （沿用）`--primary` / `--primary-soft` | `#0B7A55` / `#E4F4EB` | `#4FB08A` / `#1C2B24` | 主色分类：进行中、在做 |

对比度实测（图标于自己的 `-soft` 底上，非文本控件底线 3:1，实际全部过 4.5:1）：
`--accent-blue` **5.91 / 6.45:1**、`--accent-violet` **6.25 / 5.94:1**、`--accent-amber` **4.57 / 9.46:1**（浅色 / 深色）。

规则（越界即违规）：

- 只出现在**统计卡的图标块**（`--radius-chip` 40px 底 + 同族图标色）与卡片头图标上；不进按钮、不进进度条、不进状态灯、不做文字色。
- 同义同色：全站同一个含义只用一个分类色（如「已入库/曲目」永远是蓝色），页面不得按心情挑色。
- 四档之外不新增第五档；分类色不参与深色态的语义变化（深色只是同一色相的提亮派生，见上表）。

**命名渐变**（渐变只允许这三条，页面里不得出现 `linear-gradient(...)` 字面量）：

| 令牌 | 值 | 落点 |
| --- | --- | --- |
| `--gradient-banner` | `linear-gradient(170deg, color-mix(in oklab, var(--primary) 24%, var(--card)) 0%, color-mix(in oklab, var(--primary) 10%, var(--card)) 48%, var(--card) 100%)` | 页面横幅（`.surface-banner`，v3.7 起纵向：顶部绿意可见、底部近白——统计卡坐在上面） |
| `--gradient-brand` | `linear-gradient(135deg, var(--primary) 0%, var(--primary-hover) 100%)` | 快速操作卡头（`.surface-brand`，配 `--primary-foreground` 文字） |
| `--gradient-promo` | `linear-gradient(150deg, color-mix(in oklab, var(--primary) 22%, var(--primary-soft)) 0%, var(--primary-soft) 100%)` | 侧栏底部曲库卡（`.surface-promo`） |

- 三个令牌都引用其它令牌，深浅两态**只有一份定义**：变量在使用处解析，`--primary`/`--card`/`--primary-soft` 在 `.dark` 里已换值，渐变自动跟随。三个渐变的起点因此都用 `color-mix` 把主色掺进底里（横幅 20% 掺 `--card`、曲库卡 22% 掺 `--primary-soft`、快速操作直接取主色→hover 主色），而不是直接取 `--primary-surface`——后者在深色态几乎等于卡片底，渐变会整条消失。
- 掺入比例以「一眼看得出来」为准：低于 15% 时卡片只是微微发绿，在白色侧栏/薄荷底上会被当成没渲染出来（v3.4 落地时就踩过这个坑）。
- 渐变面上不得再叠阴影与描边以外的装饰；卡片本身的 `.card` 边框与 `--card-shadow` 保持。
- 装饰光晕（`.banner-glow`）用 `color-mix(in oklab, var(--primary) 20%, transparent)`，是唯一一处非实色装饰，`aria-hidden`。

### 5.2 顶栏与全局搜索 `TopBar.svelte`

- 高 64px，`sticky top-0`，底 `--card`，下边 1px `--border`；左侧与侧栏 Logo 区同高同基线。
- **不放页面标题**（v3.4 起）：顶栏写一遍、页头 H1 再写一遍是同一句话说两次；路由名由侧栏激活项与页头 H1 表达，顶栏把宽度让给搜索。

- 左侧内容区在 ≥768px 只占 60% 宽，给装饰留位；内容：标题（`text-h2` 600）+ 一行说明（正文 ≤40 汉字）+ **可选**的搜索块（40px 胶囊输入框 + 主按钮，`search?` 才渲染）+ 推荐词胶囊（白底 1px `--border`，hover 转 `--primary-soft`/`--primary`）。
- **搜索块是可选的**：`search={ placeholder, submitLabel, tagsLabel, tags, onsearch }` 一并给出才渲染表单与推荐词；不给就只渲染标题与说明。
- **`children` 是可选的（v3.7）**：给了就在标题区之下、横幅之内渲染（`relative mt-4`，盖过装饰层）——下载页用它放统计卡栅格，参考图的「白卡坐在横幅淡绿上」；仪表盘不传，版面不变。横幅因此是**一件两用**：要么「标题 + 搜索」，要么「标题 + 统计卡」，不出现第三种拼法。
- **推荐词是真数据**：取曲库里最近 50 条记录中出现过的**歌手名**（最多 6 个，点击即搜该歌手）；一个都取不到（空库）时整行不渲染——不摆 `#data` 这类占位词。
- 行为：搜索块**只做入口**——把关键词交给调用方跳 `/search?q=…`，自己不搜、不选源（选源与筛选只属于搜索页，§5.2）。空关键词不提交，而是把焦点交回输入框（主按钮因此保持可用，不做成灰的）。

## 6. 交互状态与反馈

### 6.1 空状态

- 组成：占位大图标（48px，`--faint-foreground`）+ 引导文案（14px，`--muted-foreground`）+ 出口按钮。
- 文案说清下一步动作，不卖萌、不空泛：下载页「还没有下载记录。点「添加链接」把 t.me 链接丢进来，或在搜索页挑一首。」（关键词/页签筛选无果时改说「没有符合条件的记录。」）；搜索页「没找到匹配的曲目。换个关键词，或换一个已启用的音乐源。」；日志页「本次连接没有错误。」
- 组件：`EmptyState.svelte`；插画不做（除了一个图标，不进图）。
- **两档外壳**（v3.6）：默认自带 `card` 外壳（整屏空态）；`bare` 去掉外壳与内边距，只留图标 + 文案 + 出口——**嵌在卡片体内**（表格体、列表体）时必须用它，否则会出现卡中卡。下载页记录表的空态就是 `bare` + 一个「添加链接」出口。

### 6.2 点击反馈

- Hover：`opacity: 0.85` **或**背景加深——导航项/列表行/图标键用**背景加深**（`--rule`），主按钮用 `--primary-hover`，链接用 `--primary-hover` 文字。
- Active：`transform: scale(0.98)`，仅用于按钮与图标键，130ms。
- 过渡：`transition: background-color 130ms ease-out, color 130ms ease-out`；`scale` 只走 `transform`（不触发 layout）。
- 禁用：`opacity: 0.5` + `cursor: not-allowed` + 不响应事件（含 `aria-disabled`）。
- 行内反馈紧贴触发控件用 `Note`（左侧 2px 色条），**不用 toast**；错误说原因与修复，成功说清改了什么。

### 6.3 响应式断点

| 断点 | 侧栏 | 顶栏 | 内容/表格 | 播放条 |
| --- | --- | --- | --- | --- |
| ≥1024px | 190px 展开（含底部曲库卡） | 搜索（最大 480px）+ 全部工具 | `max-w-[1100px]`；显示全部列 | 三分区完整 |
| 768–1023px | 64px 图标模式 | 搜索收窄至 320px | 隐藏「大小」列 | 右区收为音量图标（点击弹滑块） |
| <768px | 收进顶栏汉堡抽屉（`MobileNav.svelte`） | 搜索收为图标（点开全宽浮层） | 隐藏「大小」「入库时间」；保留「标题」+「时长」 | 封面 + 歌名 + 播/停；进度条贴底 2px 不可拖 |
| 390px（验收基准） | 抽屉 | 图标化 | 单列、无横向滚动；卡片内边距 16px | 同上 |

- 列隐藏用 CSS（Tailwind 断点类），**不改变数据获取**；路径第二行在任何断点都保留（靠省略号，不靠隐藏）。

## 7. 可访问性与动效

- **焦点**：`outline: 2px solid var(--ring)` + `outline-offset: 2px`；键盘可见焦点不得被 `overflow` 裁掉。
- **键盘**：顶栏搜索 `Ctrl/⌘+K` / `Esc`；音量与播放位置用原生 `input[type=range]` 的方向键行为；抽屉与浮层 `Esc` 关闭并把焦点还给触发键。
- **图标按钮一律 `aria-label`**；纯装饰元素 `aria-hidden="true"`。
- **状态不只靠颜色**：一律「灯 + 词」（8px 圆点 + 文字，§8），错误行除红色外必须带文字原因。
- **对比度**：见 §3.3（含实测值与 `--faint-foreground` 的使用限制）。
- **动效只有三处**：hover/active 过渡 130ms、路由内容整体淡入 140ms（`route-fade`，仅 `opacity`）、进行中状态点呼吸 1.6s（`ladder-pulse` 改名 `dot-pulse`）。`prefers-reduced-motion: reduce` 时全部关闭（含 shadcn 自带过渡）。

## 8. 状态语义与文案

状态一律「**灯 + 词**」（8px 圆点 + 文字），禁止仅用颜色表达状态；计数徽章 §5.1 用浅绿药丸，**不是**状态灯。

| 后端状态 | 灯色令牌 | 词（zh-CN） |
| --- | --- | --- |
| `queued` | `--lamp-idle`（`#7C8797`） | 等待 |
| `downloading` | `--lamp-live`（= `--primary`，呼吸） | 下载中 |
| `paused` | `--lamp-wait`（`#5B6472`） | 已暂停 |
| `success` / `skipped` | `--lamp-done`（`#1C7A4E`；与 `--lamp-live` 同色系，靠「灯 + 词」的**词**区分） | 完成 / 跳过 |
| `failed` | `--lamp-fail`（= `--destructive`） | 失败 |
| `cancelled` | `--lamp-idle` | 已取消 |

映射表只有一处实现：`web/src/lib/tone.ts`（`taskTone()` / `statusText()`），页面不得自行发明颜色或状态词。`--lamp-live/done/fail/wait/idle` 五个令牌保留（值随 §3 调整），深色态同步覆盖。

**状态事实源（v3.5）**：下载页行上的「灯 + 词」取自该行的 `history.status`——它就是这个 `history` 的生命周期状态，任务状态一变就同步写回（`downloading` / `paused` / `queued` / `cancelled` / `success` / `failed` / `skipped`），状态筛选也只认它；任务台账只补实时读数与动作 id。状态语义不变，只是历史行与任务行从此给同一个答案。

**文案规则**（文案是设计内容，不是装饰）：

1. 主动词、说结果：按钮「保存更改」→ 提示「已保存」；「加入队列」→「已加入 2 项」；禁「提交」。
2. 空态是邀请：说清下一步动作 + 给出口按钮（§6.1）。
3. 错误说原因与修复，不道歉、不含糊：「源无法访问：先用该账号加入频道，再重试。」「文件大小不符：期望 … 字节，实收 … 字节」。
4. 术语用**用户视角**的词：音乐源、落盘路径、试听、下载历史；不暴露内部实现（`sync_interval_sec`、`preview_id` 只出现在设置项与技术字段处）。
5. 全部文案走 `t("namespace.key")`（`lib/i18n/messages.ts`，zh-CN 默认 + en），组件内禁硬编码中英文案；缺键回落英文再回落键名，便于发现漏配。

## 9. 工程约束

- 组件 `<script lang="ts">` + Svelte 5 **runes**（`$state/$derived/$effect/$props/$bindable`）；禁 `on:click` 旧语法、禁 `export let`。
- TS `strict`，禁 `any`（确需用 `unknown` + 收窄）。
- API 只经 `src/lib/api/client.ts`；组件内禁裸 `fetch`。
- SSE 只在 `stores/events.svelte.ts` 订阅一次；列表事实源是 DB（下载页的下载记录走 `GET /api/history`，每行带 `task_id`；仪表盘「最近下载任务」与暂停/继续/取消/重试走 `GET /api/downloads`），SSE 只作失效信号（另有 10s 兜底轮询）。
- 统计数字只有一个来源：`GET /api/stats`（后端一次算全）→ `stores/stats.svelte.ts`。页面挂载时取一次，之后由 `events.revision` 驱动重取——不另起定时器，也**不自己数列表**（列表分页，数出来的数字会骗人）。
- 样式：Tailwind utility + §3/§2.3/§4 的令牌；禁行内样式（动态尺寸/颜色除外）；**禁令牌外颜色**（含调色板直取）。
- 令牌落地方式：`app.css` 中 `:root`（浅色默认）+ `.dark`（派生覆盖）+ `@theme inline` 映射为 utility（`bg-card`、`text-h1`、`rounded-card`、`text-caption`…）。v2.0 的 `--rule-strong`、`--meter-on/off`、`--text-micro/small/title/display` 一并删除。
- 体积与性能：不引入图形/动画库；波形为 CSS 绘制；顶栏不做 `backdrop-blur`；进度与音量共用一个 range 内核。
- 组件命名 PascalCase 多词；`ui/` 为 shadcn-svelte 生成物（可改样式、勿改 API）。
- 时间/大小/速率一律走 `lib/format.ts`；状态词一律走 `statusText()`。
- `npm run lint`（eslint + svelte-check）与 `npm run build` 必须干净。
- 初始化向导（`SetupView`）是全屏闸门，不套侧栏/顶栏/播放条。闸门在**渲染期**判定：`setupGate = session.checked && !session.setup?.complete` 为真时整页只渲染向导（控制台一帧都不渲染），并把地址栏 replace 成 `/setup`；`/api/setup/status` 没取到（后端未起、401）也算未完成——首次部署只有向导这一个入口，宁可在向导里写明原因，也不要有永久加载态或用不了的控制台。
