## 1. 引言

### 1.1 目的

本文档定义一款面向个人使用的 Telegram 音乐资源下载与管理工具的功能、约束与验收标准。读者为产品决策者与后续实现人员。

### 1.2 问题陈述

Telegram 上大量音乐以频道/群组消息（`audio`、MIME 为 `audio/*` 的 `document`）形式发布。现有通用媒体下载器（如参考项目）能批量拉媒体、用 Bot 下发链接、自定义路径前缀，但：

- 不以音乐检索为中心，缺少跨频道关键词搜索与结果预览。
- Web 端仅展示下载队列/已完成列表，频道与命名配置页处于未完成状态。
- 文件名只支持 `message_id` / `file_name` / `caption` 拼接，无法使用艺人、专辑、曲名、音质等音乐字段。
- 媒体类型过宽（照片、视频、动画等），与本产品目标不符。

本产品收敛为：**可自建频道源 → 搜索/浏览音乐 → 试听 → 下载 → 按模板落盘 → Web 管理标签与任务**。

### 1.3 产品愿景

本地常驻服务：用 Telegram 用户账号（User Client）读取已加入的频道/群组，用可选 Bot 接收链接下载指令；提供 Web 控制台管理频道、搜索、试听、标签、任务与命名规则。下载结果按用户模板写入本地音乐库。

### 1.4 范围

**范围内**

- 频道/群组作为音乐源的增删改、启用/停用。
- 在已配置源中按关键词、元数据、日期、时长、音质检索。
- 单条 / 批量 / 链接 / 转发消息下载。
- 自定义文件名与目录模板（默认 Navidrome/Jellyfin 友好的 Artist/Album/Track）。
- Web 查看任务、历史、失败重试；搜索与已下载试听；读取/编辑音频标签；响应式布局与暗色主题。
- 可选 Bot：向机器人发送 `t.me` 链接或转发音频后下载；下载完成可通知。

**范围外（本期不做）**

- 破解私密内容、绕过 Telegram 限制、未授权抓取未加入频道。
- 商业分发、公网多租户 SaaS。
- 视频、图片、`voice`、视频内音轨等非 `audio` / `audio/*` document 媒体（封面图仅作为音频附属元数据）。
- 在未添加为音乐源的对话中搜索。
- 云盘同步（rclone / 阿里云盘）——参考项目有，本期不纳入核心。
- 音乐版权授权、付费曲库对接。

### 1.5 术语

| 术语 | 定义 |
| --- | --- |
| User Client | 以用户账号登录的 Pyrogram 客户端，可读取频道历史、执行对话内音频搜索。 |
| Bot | BotFather 签发的机器人，用于接收命令与链接。Bot **不能**直接读取任意频道历史，链接解析仍走 User Client。 |
| 音乐源（Source） | 用户添加的频道或群组，用 `chat_id` / `@username` / 邀请链接标识。 |
| 音频消息 | Telegram `Message.audio`，或 MIME 为 `audio/*` 的 `document`。 |
| 模板 | 含占位符的字符串，用于生成相对路径与文件名，例如 `{artist}/{album}/{track:02d} {title}`。 |
| 游标 | 某音乐源已扫描到的 `last_message_id`，用于增量同步。 |

### 1.6 合规声明

本工具仅供用户下载其有权获取的内容（例如自己上传、已获授权、或法律法规允许的个人备份）。使用者对频道内容的合法性自行负责。实现上不提供批量爬取公开全网音乐站、不绕过付费墙。

## 2. 参考项目对照（可复用 / 需改写）

参考项目能力与本产品取舍：

| 能力 | 参考项目 | 本产品 |
| --- | --- | --- |
| Telegram User Client 登录 | Pyrogram + session | **采用**（登录、历史、搜索、下载） |
| Bot 命令下载/转发 | `/download` `/forward` 等 | **精简采用**：链接下载、转发音频、任务停止；不做转发到评论区、广告替换 |
| 多频道列表 + `last_read_message_id` | `config.yaml` 手工编辑 | **升级**：Web 增删改，持久化到数据库 |
| 下载过滤器 DSL | `message_date >= ... and file_size < 20MB` | **简化**：表单筛选 + 可选高级表达式 |
| 文件路径前缀列表 | `file_path_prefix: [chat_title, media_datetime]` | **升级**：Mustache/花括号模板 + 音乐字段 |
| 文件名前缀列表 | `message_id - file_name` | **升级**：模板；缺字段有回退规则 |
| Web：进行中/已完成、暂停、速度 | Flask + Layui，配置页注释掉 | **重做**：现代前端，配置页为 P0 |
| 媒体类型 | audio/photo/video/document/voice/animation | **仅 `audio` + MIME `audio/*` 的 document**；不含 voice、视频音轨 |
| 云盘上传 | rclone / aligo | P2 可选 |
| 代理 socks5/http | 有 | **采用** |
| Docker | 有 | P1 |
| 断点/失败重试 `ids_to_retry` | `data.yaml` | **采用**，改入库 |
| 并发 `max_download_task` | 默认 5 | **采用** |

架构建议：参考项目把配置、状态、Web、下载全揉进进程内 YAML。本产品改为 **SQLite（或同等嵌入库）存频道/任务/历史**，YAML/ENV 只放密钥与服务端口。

## 3. 用户与使用场景

### 3.1 角色

| 角色 | 说明 |
| --- | --- |
| 本地管理员 | 本机唯一用户。配置 API、登录 Telegram、管理频道与模板。 |
| Bot 授权用户 | `allowed_user_ids` 中的 Telegram 用户，可向 Bot 发链接。默认仅登录账号。 |

无多租户、无普通访客。Web 用本地密码保护即可。

### 3.2 核心场景
1. **首次启动**：Docker 部署后浏览器打开 Web，`/setup` 向导三步走完——① 密钥与代理（`api_id` / `api_hash` / 可选 `bot_token` / 可选代理）② 手机号验证码登录（生成 `sessions/` 会话文件）③ 选音乐源（可从账号对话中推荐或粘链接）。第 3 步可跳过：**放行判据是密钥 + 登录**，向导内随时能进控制台，源之后在「音乐源」页补。
2. **添加频道**：粘贴 `@channel`、`https://t.me/xxx` 或数字 id；系统解析标题、成员可见性、能否访问历史。
3. **搜索下载**：输入「周杰伦 晴天」，在已启用源中搜音频标题/表演者/文件名/caption，勾选结果批量下载。
4. **链接下载**：把 `https://t.me/c/123/456` 发给 Bot 或贴到 Web，解析后下载该条（若是相册/连续音频可展开）。
5. **盯更**：源开启「自动同步」后，定时或实时拉取新消息，命中音频规则则入队。
6. **整理曲库**：按 `{artist}/{album}/{title}` 落盘，写入 ID3，重复曲跳过。

## 4. 总体设计约束

### 4.1 运行形态

- 单机服务：一个后端进程 + 静态/内嵌 Web。
- 默认绑定 `127.0.0.1`，可改为 `0.0.0.0`（远程访问必须启用 Web 密码）。
- Linux + Docker 为主运行环境（Dockerfile + docker-compose.yml）；Windows 保留为开发环境（`python -m app`）。


### 4.2 技术选型（已锁定）

| 层 | 选型 | 理由 |
| --- | --- | --- |
| Telegram | Pyrogram User Client | 与参考项目一致；频道历史与对话内 `filter=Audio` 搜索走用户协议 |
| Bot | 同一进程内 Pyrogram Bot Client | User 下载、Bot 收指令；链接解析仍走 User Client |
| 后端 | Python 3.11+ + FastAPI | 异步下载、SSE/WebSocket 推进度 |
| 前端 | Svelte 5 + TailwindCSS + shadcn-svelte（Vite 构建） | 参考项目 Layui 配置页未完成，不继承；Svelte 编译期产出小、无虚拟 DOM，长驻本地服务不需要重运行时；Tailwind 暗色一等公民；shadcn-svelte 提供可改写的可访问组件 |
| 音频标签 | mutagen | 写 ID3/Vorbis |

### 4.3 Telegram 平台硬约束（必须在 UI 中提示）

1. **搜索不是全网搜歌**。只能搜：当前账号已加入、且已添加为音乐源的对话。
2. **私有频道** 必须先用该账号加入，否则链接解析失败。
3. **Bot 无法代替 User Client 扫频道**。无 User 登录时，Bot 只能处理「用户转发到 Bot 的音频文件」本身。
4. 下载受 Telegram 速率与洪水限制；并发默认 3–5，可配，超限要排队与退避。
5. 大文件（>2GB 视账号类型）可能失败，需记录错误而非静默丢弃。

## 5. 功能需求

优先级：P0 首版必做；P1 首版强烈建议；P2 后续。

### 5.1 账号与会话

**FR-AUTH-01（P0）首次登录**

- 配置 `api_id`、`api_hash`（来自 https://my.telegram.org/apps）。
- **前置条件可见**：密钥未配置时不发送验证码，直接说明「先去第 1 步保存密钥」；手机号必须带国家码，格式不对在本地拦下并给示例。
- 支持手机号 + 验证码；若开启 2FA，在 Web 内输入云密码（界面按服务端返回展开密码框，不要求用户预先判断账号是否开了 2FA）。
- 手机号与验证码只走本机服务，不写日志（FR-OPS-03）。
- 已有有效会话时不再要求验证码，直接告知会话仍有效。
- **连不上 Telegram（代理不可达 / 网络不通）必须给出可操作原因**（含当前代理的协议与地址），不得只回「请求失败」或长时间无响应。
- Session 落在本地 `sessions/`，权限仅当前用户可读。
- 登录成功后展示账号显示名、用户名、是否为 Premium。

**FR-AUTH-02（P0）会话保活与失效**

- 启动时复用 session；失效则 Web 提示重新登录，不删除历史任务。
- 支持登出（删除 session，不删下载文件与数据库）：入口在设置页「Telegram 账号」的「退出登录」，删除 `sessions/` 下的 User 会话文件后才算退出（留着会话文件下次启动会判「已有有效会话」直接放行）；Bot 会话是独立身份，token 未换就保留。退出登录**只退 Telegram 账号，不退 Web 控制台**（不动会话 cookie）——退出后放行判据不满足，前端闸门把人送回向导第 2 步重新登录。

**FR-AUTH-03（P0）代理**

- 支持 SOCKS5 / HTTP 代理（host、port、可选用户名密码）。
- User Client 与 Bot 共用同一代理配置。
- 代理在初始化向导与设置页都可保存；**未连接的客户端保存后立即用新配置**，已有已连接客户端时明确提示「重启服务后按新配置重连」。
- 代理的用户名/密码不回显到 Web（NFR-02）；用户只在表单里改地址/端口时，**不得静默丢弃**已有凭据。

**FR-AUTH-04（P1）Bot Token**

- 可选。未配置时 Web 链接下载仍可用。
- `allowed_user_ids` 默认 `me`；非法用户消息忽略。
- 配置了 token 时，登录成功后一并启动 Bot；**Bot 起不来不阻断登录与 Web 功能**，原因记日志。
- token 可在初始化向导第 1 步或设置页「Telegram Bot」改；换 token 后界面提示重启服务（在跑的 Bot 仍用旧 token）。

### 5.2 音乐源（频道）管理

**FR-SRC-01（P0）添加源**

输入任一种：

- `@username`
- `https://t.me/username` / `https://t.me/+invite`
- 数字 `chat_id`（含 `-100` 前缀）

系统解析并保存：id、标题、用户名、类型（channel/group/user）、能否访问历史、头像 URL（可选缓存）。

无法访问时给出明确原因：未加入、账号被封禁、链接失效、不是对话。

添加成功后**自动入队一次初始导入**（默认最近 200 条音频，作为 `sync` 任务执行、可在任务页看到），避免「加了源但什么都没发生」；后续增量与更早的历史由 FR-SRC-02 的自动同步与 FR-SRC-04 的回溯负责。

**FR-SRC-02（P0）源属性**

每个源可配置：

| 字段 | 说明 | 默认 |
| --- | --- | --- |
| 启用 | 是否参与搜索与自动同步 | 开 |
| 自动同步 | 定时拉取新消息 | 关 |
| 同步间隔 | 秒 | 120 |
| 媒体范围 | 仅 `audio`，或 `audio` + MIME 为 `audio/*` 的 document | `audio` + audio document；**不含 voice** |
| 源级过滤 | 最短/最长时长、最小码率、扩展名白名单、caption 关键词包含/排除 | 空 |
| 源级保存根目录 | 覆盖全局 `save_path` | 空=用全局 |
| 备注 | 自由文本 | 空 |

**FR-SRC-03（P0）编辑 / 停用 / 删除**

- 停用不删历史。
- 删除源：可选「仅移除源」或「同时删除该源下载记录（不删磁盘文件）」。
- 不提供「一键删磁盘文件」为默认操作，避免误删曲库。

**FR-SRC-04（P1）历史回溯**

- 对某源「从最新往回扫 N 条」或「扫到指定日期 / message_id」。
- 进度可取消；游标写入数据库，下次接着扫。
- 与参考项目 `last_read_message_id` 同类，但方向需在 UI 标明（向前增量 vs 向后补史）。

**FR-SRC-05（P1）源探测**

- 列出当前账号对话中「标题/用户名含 music、flac、mp3、无损、歌单 等关键词」的候选（关键词按词边界匹配，避免 `ost` 命中 `host` 这类误报），供一键添加；命中关键词作为该候选的标签，用于筛选。
- 每条候选展示频道名 + 句柄（或类型）+ 成员数（Telegram 未提供时留空，不猜）。
- 已添加为源的对话不再出现在候选里；非自动全量加入。
- 未登录时不返回空列表假装「没有候选」，而是明确报未登录（登录后才可能读到对话列表）。

### 5.3 搜索

**FR-SEARCH-01（P0）关键词搜索**

- 范围：已启用源，可多选。
- 匹配字段（可勾选）：音频标题、表演者、文件名、消息 caption、专辑（若 Telegram 音频对象有）。
- 使用 User Client 的对话内搜索（优先服务端 `messages.search` + `filter=Audio`），结果分页。
- 无结果、源不可达、FloodWait 要可见。

**FR-SEARCH-02（P0）结果卡片**

每条至少展示：

- 封面（有则显示，无则占位）
- 标题、艺术家、时长、文件大小、扩展名/MIME
- 来源频道、消息日期、message_id
- caption 摘要
- 「试听」「下载」「复制链接」「打开 Telegram」；已下载项试听走本地文件。

**FR-SEARCH-03（P0）二次筛选**

- 时长区间、大小区间、日期区间、扩展名（mp3/flac/m4a/ogg/wav 等）。
- 排序：相关度（默认）、日期、时长、大小。

**FR-SEARCH-04（P1）批量选择**

- 当前页全选、跨页勾选框、一键「下载所选」。
- 已在历史中存在的条目标记「已下载」，默认不重复入队（可强制）。

**FR-SEARCH-05（P2）保存搜索器**

- 命名一组关键词 + 源 + 过滤，定时执行（订阅式）。

### 5.4 链接与 Bot 下载

**FR-LINK-01（P0）解析链接**

支持：

- `https://t.me/c/<internal>/<msg>`
- `https://t.me/<username>/<msg>`
- `https://t.me/<username>/<msg>?comment=<id>`（评论区消息，能访问才下）
- `tg://` 等价形式

解析失败返回结构化错误，不入队。

**FR-LINK-02（P0）Web 粘贴链接**

- 输入框支持单条或多条（换行）。
- 非音频消息：提示类型并拒绝；若是媒体组，只下载其中的音频项并列出跳过项。

**FR-LINK-03（P0）Bot：发送链接**

- 授权用户发送上述链接 → 入队 → 回复任务 id 与标题。
- 完成后回复成功路径或失败原因。
- `/status` 最近任务；`/cancel <id>` 取消；`/help` 说明。

**FR-LINK-04（P0）Bot：转发/直接发送音频**

- 用户把音频转发给 Bot，或直接上传音频给 Bot → 按全局模板保存。
- 此路径**不依赖**频道源配置。

**FR-LINK-05（P1）Bot：消息 id 范围**（参考 `/download`）

- `/download <link> [start_id] [end_id]`：`1` 表示对话起始，`0` 表示最新（与参考项目语义对齐，须在帮助里写清）。
- 仅下载音频类消息。

**FR-LINK-06（P2）监听转发**

- 参考 `/listen_forward`：监控某对话新消息并下载。与源「自动同步」功能重叠，若 FR-SRC-02 已覆盖则本条可取消，避免两套监听。

### 5.5 下载引擎

**FR-DL-01（P0）队列**

- 全局队列，状态：`queued` / `downloading` / `paused` / `success` / `failed` / `skipped` / `cancelled`。
- 并发数可配，默认 3，上限建议 8（可在高级设置放开，但 UI 警告 FloodWait）。
- 全局暂停/恢复（参考 Web 的 Downloading/Stop）。

**FR-DL-02（P0）进度**

- 单任务：已传字节、总字节、速度、ETA。
- 全局速度。
- Web 至少 1s 刷新；优先 SSE/WebSocket，可降级轮询。

**FR-DL-03（P0）完整性**

- 下载到临时目录，校验大小（有 `file_size` 时必须一致），通过后再移动到目标路径（参考项目 `_check_download_finish` + temp→save）。
- 文件名非法字符清洗、Windows 保留名、路径长度截断（参考 `validate_title` / `truncate_filename`，上限约 230 字节）。

**FR-DL-04（P0）失败与重试**

- 记录错误码/文本（含 FloodWait 秒数）。
- 自动重试：默认 3 次，指数退避；FloodWait 等到期再试。
- 手动「重试失败项」。

**FR-DL-05（P0）去重**

默认跳过，若命中任一：

1. 同一 `(chat_id, message_id)` 已成功。
2. 同一 Telegram `file_unique_id` 已成功。
3. 目标路径已存在且大小一致。

Web 可开「强制重新下载」。P1 可增加音频指纹（chromaprint）可选去重，默认关。

**FR-DL-06（P1）断点续传**

- 若底层客户端支持 offset 续传则启用；否则至少保留临时文件，失败不污染目标目录。

**FR-DL-07（P1）封面**

- 下载 Telegram 音频缩略图，供 Web 展示；可选嵌入到音频文件（见 FR-META）。

### 5.6 命名与保存路径

这是相对参考项目的核心升级：由「前缀列表」改为「模板」。

**FR-NAME-01（P0）全局模板**

两项独立配置：

- **目录模板**（相对 `save_path`）
- **文件名模板**（不含扩展名，扩展名由真实文件决定）

示例默认：

```
save_path: D:\Music\Telegram
dir_template: {artist}/{album}
file_template: {track:02d} {title}
```

结果：`D:\Music\Telegram\周杰伦\范特西\03 晴天.flac`

**FR-NAME-02（P0）占位符**

| 占位符 | 来源 | 缺省回退 |
| --- | --- | --- |
| `{title}` | `audio.title` → 去扩展名的 `file_name` → caption 首行 → `message_{id}` | 必有 |
| `{artist}` | `audio.performer` → caption 解析 → `Unknown Artist` | |
| `{album}` | 若有（部分客户端会带）；缺省省略该目录段，不强制 `Unknown Album`（见 FR-NAME-07） | |
| `{track}` | 若有 | 空则省略 |
| `{duration}` | 秒，可 `{duration:%M:%S}` | |
| `{year}` `{date}` `{date:%Y-%m}` | 消息日期 | |
| `{channel}` `{channel_id}` | 源标题 / id | |
| `{message_id}` | 消息 id | |
| `{file_name}` | 原始文件名（去路径） | |
| `{caption}` | 消息说明，截断可配 | |
| `{ext}` | 仅文件名模板可用，一般不手写 | |
| `{bitrate}` `{size}` | 能取到才填 | 空 |
| `{unique_id}` | `file_unique_id` 短前缀，防撞名 | |

支持简单过滤器：`{caption:truncate:80}`、`{track:02d}`。非法路径字符一律替换为 `_`。

**FR-NAME-03（P0）空字段规则**

- 目录段若整段为空则省略（`{album}` 无值时不建 `Unknown Album` 文件夹）。`{artist}` 仍回退为 `Unknown Artist`。不生成多余分隔符。
- 文件名若最终为空，回退 `{message_id}`。
- 同名冲突：`title.flac`、`title (1).flac`，或附加 `{message_id}`（策略可配，默认加序号）。

**FR-NAME-04（P0）源级覆盖**

- 每个源可覆盖 `dir_template` / `file_template` / `save_path`。
- Web 提供实时预览：用一条样例元数据渲染路径。

**FR-NAME-05（P1）caption 解析规则（可选）**

许多频道不填 `audio.title`，把「艺人 - 歌名」写在 caption。提供可开关规则：

- 正则，默认 `^\s*(?P<artist>.+?)\s*[-–—]\s*(?P<title>.+?)\s*$`
- 仅当官方字段为空时启用。

**FR-NAME-06（P1）日期格式**

- 全局 `date_format`，默认 `%Y-%m`，用于 `{date}` 默认形态。与参考项目 `date_format` 对齐。

**FR-NAME-07（P1）Navidrome / Jellyfin 友好默认目录（原 S-03）**

- 出厂默认模板为 `{artist}/{album}` + `{track:02d} {title}`，媒体服务器可直接扫描 `save_path`。
- 设置页提供预设：「Navidrome/Jellyfin」「按频道归档 `{channel}/{artist}`」「扁平 `{artist} - {title}`」；选预设写入模板，用户仍可手改。
- `{album}` 缺失时该目录段省略（见 FR-NAME-03），不强制生成 `Unknown Album` 文件夹；预设旁注明此回退。
- 不实现 Navidrome/Jellyfin 的 API 对接、扫描触发或 playlist 同步。

### 5.7 音频元数据写入

**FR-META-01（P1）下载时写入标签**

下载成功后用 mutagen 写入（不改变音轨数据）：

- ID3（mp3）/ Vorbis Comment（flac/ogg）/ MP4（m4a）：title、artist、album、track、year。
- 可选嵌入封面。
- 开关默认开；失败只记日志，不把任务标失败。
- Web 侧事后读写见 FR-TAG-01 / FR-TAG-02。

**FR-META-02（P2）外部补全**

- MusicBrainz / AcoustID 识别。默认关，需用户明确启用。

### 5.8.2 试听

**FR-PLAY-01（P1）已下载播放**

- 历史记录、任务成功行提供播放。音频从本机 `save_path` 经认证 HTTP 流出（`Range`），不把目录裸暴露。
- 底栏播放器：播放/暂停、拖动进度、音量、上一首/下一首（当前列表上下文：历史筛选结果或搜索已下载项）。
- 同一时刻一首；切歌停上一首。
- 浏览器不支持的编码（少见 codec）：提示「无法在浏览器播放，可打开本地文件」，不崩溃。目标格式：mp3、m4a/aac、ogg/opus、wav；flac 在 Chromium 可用则播，否则同样提示。

**FR-PLAY-02（P1）搜索结果试听（未下载）**

- 搜索卡片「试听」：用 User Client 拉取该消息音频，写入 `temp/preview/`，再按 FR-PLAY-01 同样方式流出。
- 试听不是下载入队，不写 `save_path`、不写成功历史（可写 preview 缓存记录）。
- 缓存上限可配，默认 512MB 或 50 个文件，LRU 淘汰。
- 用户点「下载」仍走正式队列；若预览文件已完整且校验通过，允许直接搬到目标路径以避免二传（可选优化，失败则正常下载）。
- FloodWait / 无权限：试听按钮显示错误，不影响其它卡片。
- 不实现 Telegram 流式边下边播为 P1 必达；允许「先缓冲到可播再开始」（目标：普通 5–10MB 曲 < 15s 出声，受网速限制须显示缓冲状态）。

**FR-PLAY-03（P1）播放与下载互不阻塞**

- 试听占用独立于 `max_download_task` 的 1 个预览槽，默认并发预览 1，避免搜列表连点打满 FloodWait。
- 下载队列不因播放暂停。

### 5.8.3 标签读取与编辑

**FR-TAG-01（P1）读取**

- 对已下载且文件仍在磁盘的记录：用 mutagen 读标签，Web 详情展示。
- 字段（有则显示，无则空）：title、artist、album、albumartist、track、tracktotal、disc、year/date、genre、comment、duration、bitrate、sample_rate、channels、codec/container、封面（有则缩略图）。
- 同时展示「Telegram 侧」快照（下载时的 title/performer/caption）与「文件内标签」，两者可能不一致，UI 分栏，避免 silently 混用。
- 文件缺失：标明「文件不在磁盘」，只读 Telegram 快照，禁止保存标签。

**FR-TAG-02（P1）编辑并写回文件**

- 可编辑：title、artist、album、albumartist、track、tracktotal、year、genre、comment。
- 封面：保留 / 替换（上传 jpg/png，限制 5MB）/ 删除嵌入封面。
- 保存：只改标签块，不重编码音轨。mp3→ID3v2.3 或 2.4（实现选一种并在设置写明）；flac/ogg→Vorbis Comment；m4a→MP4 tags。
- 写成功后更新 DB 中 title/artist/album 等展示字段，供历史/搜索已下载过滤。
- **默认不因改标签而重命名/移动文件**。提供可选「按当前模板重命名」（单独按钮，预览新旧路径，确认后 `os.replace`；目标已存在则中止并提示）。
- 校验：必填无；空 title 允许；track 须为整数或空。失败（文件占用、权限、不支持的容器）回滚展示，任务不标下载失败。
- 不支持：cue/ape/wma 等非目标容器的编辑（只读提示不支持）。

**FR-TAG-03（P1）与下载写入的关系**

- FR-META-01 是入盘时的自动写入；FR-TAG-02 是事后人工修正。后写覆盖文件内对应帧。
- 正在 `downloading` 的文件禁止编辑标签。


### 5.8.4 完成通知

**FR-NOTIFY-01（P1）下载完成通知（原 S-10）**

- 单任务成功/失败：可选浏览器 Notification（需授权），以及向 Bot 授权用户发 Telegram 消息（路径或错误摘要）。
- 批量：过程中不逐条刷屏；结束发汇总（成功 n / 失败 m / 跳过 k）。

### 5.9 配置与数据持久化

**FR-CFG-01（P0）**

- 密钥：`config.yaml` 或 `.env`（`api_id`、`api_hash`、`bot_token`、`web_login_secret`、代理）；Docker 下支持 `TGM_*` 环境变量与 `TGM_BASE_DIR` 路径布局覆盖。
- 部署路径（FR-CFG-02）同源：`config.yaml` 的 `save_directory`/`session_directory`/`temp_directory`，或同名 `TGM_*` 环境变量（env 优先）。
- 业务数据：SQLite（源、任务、历史、游标、设置中的模板）。
- 不把下载历史只写 YAML。

**FR-CFG-02（P0）路径**

```
save_path/          # 用户曲库
temp/               # 下载中
temp/preview/       # 搜索试听缓存（LRU）
sessions/           # telegram session
data/app.db         # sqlite
logs/               # 滚动日志
```

- 默认相对 `TGM_BASE_DIR`（源码根；Docker 为 `/data`）展开，默认目录名 `downloads`（曲库）、`sessions`、`temp`；`data/`、`logs/` 固定相对基准目录，不单独配置。
- 三项可覆盖为绝对路径：`save_directory`（曲库）、`session_directory`（会话）、`temp_directory`（临时与试听缓存，`temp/preview` 为其子目录）。
- Docker 示例：`/data/downloads`、`/data/sessions`、`/data/temp`（`docker-compose.yml` 以 `TGM_SAVE_DIRECTORY` 等指定并挂载同名卷）。
- Windows 上 `/data/...` 这类无盘符写法锚定到基准目录所在盘（如 `C:\data\downloads`），不随进程当前盘漂移。

**FR-CFG-03（P1）导出/导入源列表**

- JSON/CSV：username、备注、模板覆盖。不含 session。

### 5.10 运维与安装

**FR-OPS-01（P0）**

- `README`：申请 API、登录、添加频道、模板说明、代理。
- 一种启动方式：`python -m app` 或等效脚本。

**FR-OPS-02（P1）Docker Compose + Web 初始化**

- Linux 为主运行环境，Docker 部署：卷挂载 `save_path`（`/data/downloads`）、`sessions`（`/data/sessions`）、`temp`（`/data/temp`）、`data`（SQLite）。
- 首次部署 `docker compose up -d` 后，浏览器打开 Web **在界面内完成全部初始化**，向导固定三步，不做「先 compose run 再 up -d」的前台交互：
  1. **密钥与代理**：`api_id` / `api_hash` / `bot_token`（可选）/ 代理（可选，可关闭）。保存前逐项校验（数字位数、十六进制长度、`bot_token` 形状、端口范围），**校验不通过就不写 `config.yaml`** 并把待修项一次列全；写入后清空「走代理」表示直连（清除代理段）。
  2. **登录账号**：手机号 + 验证码（2FA 按需输入云密码），会话文件生成在 `sessions/`。密钥未齐备时不允许进入本步。
  3. **音乐源**（可跳过）：从账号对话推荐候选，或粘链接/`@用户名` 手动添加。邀请链接（`t.me/+…`）明确拒绝并说明「先用账号加入再粘用户名」。
- **放行判据 = 密钥齐备 + 已登录**：未满足时 Web 强制停留在向导，其余页面不可达；音乐源可跳过，进控制台后在「音乐源」页补。前端闸门在**渲染期**判定——只有确认 `complete=true` 才渲染控制台，否则整页就是向导（不先闪一下控制台再跳走）；状态接口没取到（后端没起、401）也按未初始化处理，停在向导并在页头写明原因（首次部署只有这一个入口），不出现永久加载态。
- **前端产物**（`web/dist`）跟随**代码**位置（源码根；Docker 镜像内为 `/opt/app/web/dist`），不跟随 `TGM_BASE_DIR`——Docker 里数据在 `/data`、代码在 `/opt/app`，用数据目录拼路径会让首屏 404，向导不可达。产物在别处时用 `TGM_STATIC_DIR` 覆盖。产物缺失时非 `/api` 请求返回一段构建说明（`cd web && npm install && npm run build`，或 `./run.sh`；Docker 需在构建镜像前先构建），而不是一行 404 JSON。
- 向导内保存的密钥对**尚未连接**的客户端立即生效（保存后可直接登录），不需要为了登录先重启；已连接客户端在界面提示重启后生效。
- 配置修不好（例如代理不可达）时**服务仍要起得来**：启动期连不上 Telegram 只记警告，Web 与向导照常可用，否则用户没有入口去改配置。
- 手机号与验证码只走本机、不进日志（FR-OPS-03）。
- 初始化密钥由 `POST /api/setup/secrets` 写入 `config.yaml`（不入库）。文件位置 = `TGM_BASE_DIR/config.yaml`（Docker 为 `/data/config.yaml`），需挂卷/bind mount 才随容器重建保留；向导内保存对尚未连接的客户端立即生效，已连接客户端按上面的重启提示处理。
- **重新执行初始化**（设置页入口，`POST /api/setup/reset`）：删除 `config.yaml` 的 `api_id`/`api_hash`/`bot_token`/`proxy`，退出登录并删除 User 与 Bot 会话文件（换 token 后旧 Bot 会话会复用旧身份），随后回到向导第 1 步。**保留**：`web_login_secret`/`web_host`/`web_port`、部署路径、下载文件、下载历史、音乐源。前端随后按放行判据被闸门送回 `/setup`。

**FR-OPS-03（P1）日志**

- 级别可配；默认不把手机号、验证码写入日志。

## 9. 界面信息架构（示意）

```text
侧栏 230px（768–1023px 塌为 64px 图标模式；<768px 收为顶栏汉堡抽屉）
  音乐库（图标 + 系统名 + 识别码）
  仪表盘 / 搜索 / 下载任务（进行中计数）/ 下载历史 / 音乐源 / 设置 / 日志（错误计数）

顶栏 64px（全站常驻，不随路由变化）
  页面标题 | 全局搜索（Ctrl K → /search?q=，源选择留在搜索页）
  在传任务数 | 总速率（没有在传时不占位）
  外观（跟随系统 / 浅色 / 深色）| 通知 | 连接状态 + 账号头像

内容区（左对齐，max-width 1100px，内边距 24px）
  页头：标题 + 一行上下文 + 右侧计数或动作
  主体：卡片内的数据表/列表行；数值列等宽右对齐

播放条 76px（全站常驻）
  封面 / 标题 / 艺人 → 随机 · 上一首 · 播停 · 下一首 · 循环 → 时间码 + 进度（线型或波形，可拖动）→ 音量、队列
```

- 仪表盘首屏：淡绿状态卡承载正在写入的传输（真实字节/速率/剩余）+ 最近落盘路径；下方为队列事实与最近入库。
- 音乐源「添加」：链接输入 → 服务端校验 → 列表追加；失败即为行内错误（原因 + 修复）。
- 音乐源「回溯」：方向 + 条数上限对话框 → 入队为下载任务。
- 音乐源「移除」：确认对话框，可选「同时删除该源的历史记录」。
- 设置「模板」：左右分栏，左编辑，右实时预览落盘路径；并发与试听缓存上限标注「下次启动生效」。
- 设置「账号与连接」：账号行（灯 + 显示名/用户名/Premium）+ 退出登录（确认对话框）；Bot token 与代理各自一张卡，保存后按 `restart_required` 说明「立即生效」还是「重启服务」；末尾「重新执行初始化」卡（确认对话框里写清会清掉什么、保留什么）。
- 历史行：播放 / 复制路径 / 重新下载；落盘路径为行的第二行一级文本。
- 标签编辑抽屉：见 SDD §5.2，后端 `/api/history/{id}/tags` 路由未实现前不提供。

## 11. 验收标准

**P0**

1. 使用真实 Telegram 测试账号登录后，Web 显示账号名。
2. 添加一个含音频的公开频道，搜索已知曲名能出结果，字段含标题或文件名、时长、来源。未添加的对话不出现在搜索范围。
3. 从搜索结果下载一首，磁盘路径符合当前模板；刷新历史可见成功记录。
4. 修改模板后再下一首，新路径生效，旧文件不被改名。
5. 向 Bot 发送该频道一条音频消息链接，下载成功并回复。
6. 向 Bot 转发一首音频，保存成功。
7. 同一条消息再下，默认跳过并标记 skipped。
8. 下载中点击全局暂停，传输停止；恢复后继续或重入队（行为在实现时写进帮助，须一致）。
9. 故意填错误链接，Web 与 Bot 均返回失败原因，不崩溃。
10. 关闭进程再启动，源列表与历史仍在，session 无需重登。
11. voice / 视频消息不会入队；仅 `audio` 与 `audio/*` document。

**P1（随 M4）**

12. 默认模板下载后的相对路径为 `{artist}/{album}/{track:02d} {title}.ext`；无专辑时路径为 `{artist}/{track:02d} {title}.ext`。
13. 设置页切换「按频道归档」预设后，新下载路径变为 `{channel}/{artist}/...`。
14. 浏览器授权通知后，Web 任务完成弹出 Notification；Bot 任务完成仍有 Telegram 回复。
15. 390px 宽下可完成：打开搜索、添加源、查看任务、底栏播放；可切换深色主题。
16. 历史中一首已下载 mp3：点播放后底栏出声，暂停/拖动进度有效；未登录请求 `/stream` 被拒绝。
17. 搜索一条未下载音频：点试听后出现缓冲状态，随后出声；`save_path` 不新增文件；再点下载仍可入队。
18. 打开已下载曲的标签：展示文件内 title/artist；修改 title 保存后，用 mutagen/其它标签工具打开该文件可见新 title，音轨时长不变；历史列表标题同步。
19. 改标签时不勾选重命名：磁盘路径不变。点「按模板重命名」并确认后路径更新，旧路径不留文件。
20. Linux Docker 部署后，Web `/setup` 向导内完成 api_id/api_hash/bot_token/代理保存（写入 config.yaml）与手机号验证码登录，`sessions/` 生成会话文件，重启容器后无需重登。
21. 向导第 1 步填错（`api_id` 位数不对、`api_hash` 非 32 位十六进制、代理端口越界）时**不写 `config.yaml`**，行内一次列出全部待修项；改正后保存成功，且登录立即用新密钥。
22. 密钥已配置但未登录时，除 `/setup` 外访问任何页面都被送回向导；登录完成后放行；第 3 步不加任何音乐源也能进控制台。
23. 代理不可达时点「发送验证码」，界面在可接受时间内给出「连不上 Telegram（当前代理 …）」这类带修复方向的原因，不出现无响应的等待或空泛报错。
24. 向导第 3 步从账号对话推荐候选（含句柄/成员数/命中标签），一键添加后该候选从推荐列表消失、出现在「已添加」里；添加动作同时产生一条最近 200 条的一次性导入任务，可在下载任务页看到。
25. 设置页「Telegram 账号」显示当前账号（灯 + 显示名 / @用户名 / Premium）；点「退出登录」并在确认对话框确认后 `sessions/musicdown.session` 被删除，界面回到向导第 2 步，重新登录仍需输入验证码；下载历史与音乐源不受影响。
26. 设置页改代理或 bot_token 后写入 `config.yaml`：未连接的客户端提示立即生效，已连接客户端提示重启服务；代理的用户名/密码填了才覆盖，留空沿用已存值，且回读不显示。
27. 设置页「重新执行初始化」确认后：`config.yaml` 的 `api_id`/`api_hash`/`bot_token`/代理消失，`web_login_secret` 与 `save_directory` 等部署路径保留；User 与 Bot 会话文件均被删除；界面回到向导第 1 步且各项状态显示为缺失；下载历史与音乐源仍在。
28. 全新部署（无 `config.yaml`、无 `sessions/`、`TGM_BASE_DIR` 指向别处）打开任意 URL（`/`、`/dashboard`、`/setup`）：首屏直接是向导第 1 步，DOM 里没有侧栏/顶栏/播放条，地址栏被 replace 成 `/setup`；把 `TGM_BASE_DIR` 换成任意目录（含 Docker 的 `/data`）都不影响前端产物定位。
29. 前端产物缺失时（本地没构建、`TGM_STATIC_DIR` 指空）：非 `/api` 请求返回构建说明（503 文本），`/api/*` 仍返回 JSON 404，日志记 error；构建后同一进程重启即恢复。
